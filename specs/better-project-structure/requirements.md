# 需求文档
## 简介
本需求用于改进 Fun Harness 中 product-structure（项目结构提取与摘要）生成质量，解决现有目录结构提取颗粒度过粗/过细、提示词约束过强导致 AI 输出质量受限的问题。目标是在不破坏现有流程契约的前提下，引入“样例驱动提取”能力，使 AI 能依据可配置样例标准自动完成结构提取与结果生成，并保持可追溯、可测试与可回归。

## 术语表
- Product Structure：由项目目录与关键文件语义归纳得到的结构化产物，用于后续设计/任务/实现阶段输入。
- 目录颗粒度：目录与文件在结构输出中的抽象层级，过粗会丢失关键信息，过细会引入噪声。
- 样例驱动提取：以预置样例（含目标格式、保留/忽略规则、层级策略）引导 AI 输出，而非仅依赖固定提示词。
- 提取规则配置：可被系统读取的规则集合，包含包含路径、排除路径、层级深度、聚合策略等。
- 质量门禁：对输出结构进行机器校验与人工评审的流程控制。

## 需求清单
### 需求-1：支持样例驱动的结构提取输入
**用户故事：** 作为需求/设计阶段操作者，我希望为结构提取提供可配置样例，以便 AI 按统一标准输出高质量项目结构。
#### 验收标准
1. GIVEN 存在合法样例文件 WHEN 触发结构提取 THEN 系统必须将样例内容作为提取输入的一部分传递给 AI。
2. GIVEN 样例文件缺失或不可读 WHEN 触发结构提取 THEN 系统必须返回明确失败信息并指明缺失路径，不得伪造成功结果。
3. GIVEN 同一项目与同一样例 WHEN 重复执行提取 THEN 输出结构的主层级与命名策略必须保持一致。

### 需求-2：优化目录颗粒度控制机制
**用户故事：** 作为项目分析者，我希望系统可根据规则控制结构颗粒度，以便避免结构过粗或过细。
#### 验收标准
1. GIVEN 配置了层级深度与聚合规则 WHEN 执行提取 THEN 输出必须遵循配置限制并体现目录聚合结果。
2. GIVEN 项目存在大量重复模式目录 WHEN 执行提取 THEN 系统必须按规则进行归并展示，避免噪声级重复节点。
3. GIVEN 关键领域目录被标注为必须展开 WHEN 执行提取 THEN 输出必须保留其细粒度子结构。

### 需求-3：放宽提示词硬限制并保持约束可控
**用户故事：** 作为流程治理者，我希望 AI 提示词从“强限制模板”调整为“样例+规则约束”模式，以便在保证一致性的同时提升 AI 发挥空间。
#### 验收标准
1. GIVEN 启用样例驱动模式 WHEN 组装 AI 请求 THEN 请求内容必须包含样例标准、规则约束与输出格式要求三部分。
2. GIVEN 提示词模板更新 WHEN 执行结构提取 THEN 不得破坏既有输出契约字段（如标题、层级、关键模块说明）。
3. GIVEN 同一输入代码库 WHEN 对比旧模式与新模式 THEN 新模式输出必须在可读性或信息完整性上至少满足“不低于旧模式”的门禁判定。

### 需求-4：建立提取结果质量校验与失败阻断
**用户故事：** 作为质量负责人，我希望在结构产物落地前执行机器校验，以便阻断不合格结果进入后续阶段。
#### 验收标准
1. GIVEN 提取结果缺失必填段落或结构字段 WHEN 运行门禁校验 THEN 流程必须阻断并输出失败原因。
2. GIVEN 提取结果通过结构合法性检查 WHEN 进入后续阶段 THEN 系统必须记录可追溯的校验通过标记。
3. GIVEN 门禁失败 WHEN 用户查看日志 THEN 日志必须包含失败规则 ID、问题位置与修复建议。

### 需求-5：保持需求到产物的追溯闭环
**用户故事：** 作为审计人员，我希望本能力变更具备 Req-* 级追溯关系，以便验证需求、设计、任务与测试的一致性。
#### 验收标准
1. GIVEN 任一需求 Req-* WHEN 查询追溯矩阵 THEN 必须可定位对应设计条目、任务项与测试用例。
2. GIVEN 存在无 Req-* 来源的实现变更 WHEN 执行追溯检查 THEN 门禁必须失败并阻断合并。
3. GIVEN 需求文本被修订 WHEN 重新生成追溯矩阵 THEN 历史映射关系必须可增量更新且不产生冲突 ID。

| Req-1 | 样例输入契约、样例加载失败协议 | apps/src/services/projectStructureService.ts | 样例可读/不可读路径、错误阻断 |
| Req-2 | 颗粒度规则模型、聚合策略 | apps/src/services/projectStructureService.ts | 深度控制、关键目录展开、重复目录归并 |
| Req-3 | 提示词组装策略与契约稳定性 | apps/src/services/promptService.ts, apps/src/services/aiDispatchService.ts | 结构字段稳定性、信息完整性对比 |
| Req-4 | 质量门禁规则、失败协议、日志规范 | apps/src/services/projectStructureService.ts, apps/src/services/specDeltaService.ts, apps/src/services/harnessLog.ts, apps/src/harnessMessageController.ts | 结构校验通过/失败分支、门禁日志字段完整性 |
| Req-5 | 追溯关系聚合、快照输出与断裂检查 | apps/src/specTrace.ts, apps/src/services/taskStoreService.ts | Req 绑定完整性、traceMatrix 快照、无来源实现阻断 |
