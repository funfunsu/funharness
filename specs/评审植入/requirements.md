# 需求文档
## 简介
本需求文档定义“评审植入”能力：在主流程关键阶段提供可选评审入口，评审提示词支持系统通用模板与用户自定义模板两种来源。评审提示词必须按阶段区分，不同环节使用不同 prompt。评审行为按需触发，不阻断主流程。

## 术语表
- 评审植入：在阶段节点提供“发起评审”入口与对应执行能力。
- 关键阶段：需求、设计、测试用例、任务拆解四个主流程节点。
- 通用评审 Prompt：系统预置、可复用且按阶段区分的评审提示词模板。
- 自定义评审 Prompt：用户提供且按阶段独立配置的评审提示词模板。
- 非强制评审：用户不触发评审时，流程可继续推进。

## 需求清单
### 需求-1：关键阶段提供可选评审入口
**用户故事：** 作为流程使用者，我希望在需求、设计、测试用例、任务拆解阶段看到可点击的评审入口，以便于在关键节点按需发起质量检查。
#### 验收标准
1. GIVEN 用户进入需求阶段 WHEN 阶段页面加载完成 THEN 系统展示可点击的“评审”入口且默认未执行评审。
2. GIVEN 用户进入设计阶段 WHEN 阶段页面加载完成 THEN 系统展示可点击的“评审”入口且默认未执行评审。
3. GIVEN 用户进入测试用例阶段 WHEN 阶段页面加载完成 THEN 系统展示可点击的“评审”入口且默认未执行评审。
4. GIVEN 用户进入任务拆解阶段 WHEN 阶段页面加载完成 THEN 系统展示可点击的“评审”入口且默认未执行评审。
5. GIVEN 用户未点击任一阶段评审入口 WHEN 用户继续主流程 THEN 主流程可继续且不因未评审而阻断。

### 需求-2：评审提示词支持通用模板
**用户故事：** 作为流程使用者，我希望系统提供一套通用评审 Prompt，以便于无需额外配置即可快速发起评审。
#### 验收标准
1. GIVEN 用户在任一关键阶段点击评审 WHEN 用户未配置自定义 Prompt，或当前解析流程未提供该阶段自定义配置 THEN 系统使用该阶段对应的通用评审 Prompt 发起评审。
2. GIVEN 系统使用通用评审 Prompt 发起评审 WHEN 评审请求被创建 THEN 请求内容包含当前阶段上下文信息与通用模板正文。
3. GIVEN 用户在不同关键阶段分别发起评审 WHEN 系统构造请求 THEN 每次使用与当前阶段匹配的通用评审 Prompt。
4. GIVEN 需求、设计、测试用例、任务拆解四个阶段均可发起评审 WHEN 分别查看四阶段所用通用 Prompt THEN 四者模板内容可区分且不应为同一份未分阶段模板。

### 需求-3：评审提示词支持用户自定义并可覆盖通用模板
**用户故事：** 作为流程使用者，我希望按阶段配置自定义评审 Prompt，以便于贴合团队评审标准。
#### 验收标准
1. GIVEN 用户已为某关键阶段保存自定义 Prompt WHEN 在该阶段点击评审 THEN 系统优先使用该阶段自定义 Prompt 发起评审。
2. GIVEN 用户已为某关键阶段保存自定义 Prompt WHEN 用户更新并再次保存 THEN 后续评审使用最新保存版本。
3. GIVEN 用户未为某关键阶段保存自定义 Prompt WHEN 在该阶段点击评审 THEN 系统回退使用通用评审 Prompt。
4. GIVEN 用户为需求阶段配置了自定义 Prompt 且设计阶段未配置 WHEN 分别在两个阶段发起评审 THEN 需求阶段使用自定义模板且设计阶段使用通用模板。
5. GIVEN 用户分别为需求阶段与设计阶段配置不同自定义 Prompt WHEN 分别发起评审 THEN 两阶段请求必须使用各自阶段配置，且不得互相复用。

### 需求-4：评审执行结果与状态可感知且不改变主流程完成语义
**用户故事：** 作为流程使用者，我希望看到评审执行状态与结果摘要，以便于判断是否需要修订产物，同时不影响阶段本身可完成性。
#### 验收标准
1. GIVEN 用户点击评审入口 WHEN 评审任务开始执行 THEN 界面显示评审进行中状态。
2. GIVEN 评审任务成功完成 WHEN 界面查询到该阶段最新评审状态 THEN 界面显示可读取的评审结果摘要并标记完成状态。
3. GIVEN 评审任务执行失败 WHEN 界面查询到该阶段最新评审状态 THEN 界面显示失败状态与可理解的失败原因。
4. GIVEN 某阶段评审失败或未执行 WHEN 用户执行阶段正常保存或推进操作 THEN 阶段操作按既有规则处理，不新增“必须评审后才能继续”的强制约束。
